# Отладка

Отладка выполнялась двумя способами: в VS Code (конфигурация *Python File* и
*Отладка update_quantity* из `.vscode/launch.json`, F5 / F10 / F11) и в
консольном отладчике `pdb` — его протокол приведён ниже, потому что он
полностью повторяет шаги VS Code (точка останова, просмотр переменных, Step Over).

## Сеанс 1. `get_low_stock` — проверка логики

**Точка останова:** `shop.py`, строка `return sorted(low, ...)` в `get_low_stock`.
**Запуск:** `python -m pdb debug_low_stock.py` → `b shop.py:119` → `c`.

| Переменная | Значение в точке останова |
|------------|---------------------------|
| `limit` | `3` |
| остатки по товарам | `[10, 2, 12, 6, 3, 9]` |
| `low` | `['Бутсы Strike FG', 'Куртка ветрозащитная']` |

Остаток 3 (куртка) попадает в список — граница `<= 3` работает верно.
Step Into (`s`/F11) заводит в `lambda` ключа сортировки — видно, что сортировка
идёт по сумме остатков. **Ошибок не найдено.**

## Сеанс 2. `update_quantity` — найденная ошибка

Тест `test_update_to_zero_removes_item` упал (`[1, 4] != [4]`). Для поиска
причины написан `debug_update.py`, точка останова — строка `item["qty"] = new_qty`.

| Шаг | `new_qty` | `stock` | `item["qty"]` |
|-----|-----------|---------|---------------|
| до строки (остановка) | 0 | 2 | 1 |
| после Step Over (F10) | 0 | 2 | **0** |

Позиция с количеством 0 остаётся в корзине: функция не обрабатывает ноль и
отрицательные значения (тест `test_negative_quantity_rejected` принимал −2).

**Исправление:**
```python
if new_qty < 0:
    return False, "Количество не может быть отрицательным"
if new_qty == 0:                      # 0 = удалить позицию
    cart.remove(item)
    return True, "Позиция удалена"
```
После исправления все 32 теста проходят.

## Приёмы
- **Continue (F5)** — до следующей точки останова;
- **Step Over (F10)** — выполнить строку целиком;
- **Step Into (F11)** — войти в вызываемую функцию (`lambda`, `find_product`);
- **Step Out (Shift+F11)** — вернуться в вызывающий код;
- панель **Variables** / команда `p` — значения переменных.
