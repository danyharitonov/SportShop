# Схема ветвления Git Flow для «СпортТовары»

```
main     ●────────────────────────●──────────────●(v1.0)
          \                      / hotfix/       /
hotfix     \                    ●  cart-total   /
            \                  / \             /
develop      ●──●───●──●──────●───●──────●────●
                 \ /    \  \    /        /
feature/low-stock ●      \  ●──● total  /
                          ●──── (v1, v2)   search-advanced ●
```

| Ветка | Назначение | Откуда создаётся | Куда сливается |
|-------|------------|------------------|----------------|
| `main` | только выпущенные версии (теги `vX.Y`) | — | — |
| `develop` | интеграция готовых функций | `main` | `main` при выпуске |
| `feature/<имя>` | одна история из backlog (US-N) | `develop` | `develop` |
| `hotfix/<имя>` | срочное исправление выпущенной версии | `main` | `main` и `develop` |

## Правила проекта
1. В `main` напрямую не коммитим.
2. Имя feature-ветки отражает историю: `feature/low-stock` → US-1.
3. Сообщение коммита начинается с номера истории: `US-1: ...`.
4. Feature-ветка сливается через «Pull Request» (описание в `docs/10_Pull_Request.md`),
   слияние с `--no-ff`, чтобы в графе была видна граница функции.
5. После слияния ветка удаляется.
