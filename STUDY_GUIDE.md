# Как разобраться в проекте «СпортТовары» перед защитой

Шпаргалка: что где лежит, как работает и что ответить преподавателю.
Читай по порядку и открывай файлы в VS Code.

## 1. Что это за проект
Консольный магазин спорттоваров. Данные — в `data/products.json`, заказы —
в `data/orders.json`. Запуск: `python main.py`, проверка всего сразу:
`python build.py`.

Проект делался по практическим работам — каждая оставила след в репозитории:

| ПР | Что смотреть |
|----|--------------|
| 1–4 | `practice_1-4/` — вариант «Туроператор»: анализ, ТЗ, диаграммы, классы `turofis/` |
| 5 | `pr05_ChudoObuv/main.py` — задания по основам Python |
| 6 | `docs/03…07` — backlog, спринт, Kanban, стендап, ретро; коммиты `US-N: …` |
| 7 | `docs/08…12` — Git Flow, конфликт, PR, hotfix; `git log --graph --all` |
| 8 | `tests/test_shop.py`, `docs/13…14`, `debug_*.py` |
| 9 | папка `src/`, `tests/test_integration.py`, `build.py`, `docs/15…16` |
| 10 | `README.md`, `docs/17…21`, тег `v1.0` |

## 2. Как устроен код (src/)
```
main.py ─► storage  (читает/пишет JSON, размеры → int)
        ─► catalog  (поиск, низкий остаток, средняя цена)
        ─► cart     (корзина, скидка 10 % от 10 000 ₽)  ──► catalog.find_product
        ─► orders   (заказ, чек, JSON)                  ──► cart.cart_total
        ─► analytics(выручка, средний чек, хит продаж)
```
- **Товар** — словарь: `id, name, category, brand, price, sizes {размер: остаток}`.
- **Позиция корзины** — `product_id, name, size, qty, price`.
- `add_to_cart` возвращает пару `(True/False, сообщение)` — так меню знает, что напечатать.
- `shop.py` — «переходник»: старые тесты импортируют из него, а он берёт всё из `src/`.

## 3. Что показать на защите
```bash
python build.py                          # 5 шагов, «Сборка успешна!»
python -m unittest discover -s tests -v  # 41 OK
git log --oneline --graph --all          # ветки, конфликт, hotfix, теги
python main.py                           # 2 → поиск, 4 → корзина, 6 → заказ, 7 → аналитика
```

## 4. Вопросы, которые точно спросят
- **Scrum и Kanban?** Scrum — спринты фиксированной длины с ролями и
  церемониями; Kanban — непрерывный поток задач по колонкам с WIP-лимитом.
- **User Story?** «Как <роль>, я хочу <действие>, чтобы <цель>» + критерии приёмки.
- **Как возник конфликт?** Ветки total-v1 и total-v2 изменили одни строки
  `total_sum`. Оставил версию с количеством (`price × quantity`).
- **Зачем hotfix в две ветки?** В `main` — чинит выпущенную версию, в `develop` —
  чтобы ошибка не вернулась в следующем релизе.
- **Какую ошибку нашли тесты?** `update_quantity(…, 0)` оставлял позицию с 0 шт.,
  а отрицательное количество принималось. Исправлено.
- **Модульный vs интеграционный тест?** Первый проверяет одну функцию, второй —
  что модули правильно передают друг другу данные (например, ключ `name`).
- **Что делает build.py?** Версия Python → файлы → JSON → тесты → старт `main.py`.
- **Зачем тег v1.0?** Навсегда помечает выпущенную версию; к ней можно вернуться.

## 5. Если попросят изменить что-то на месте
- Порог «мало на складе»: параметр `limit` в `get_low_stock` (по умолчанию 3).
- Скидка: `DISCOUNT_RATE` / `DISCOUNT_THRESHOLD` в `src/cart.py`.
- Новый товар: добавь объект в `data/products.json`, запусти `python build.py`.
